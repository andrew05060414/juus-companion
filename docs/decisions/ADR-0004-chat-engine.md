# ADR-0004：单聊引擎规格

> 创建日期：2026-09-26 ｜ 最后更新：2026-09-26 ｜ 版本：v0.1 ｜ 状态：提议
> 对应任务：[GitHub Issue #4](https://github.com/andrew05060414/juus-companion/issues/4)

## 摘要

啾信单聊不直接嵌入 SillyTavern、RisuAI、TauriTavern 或 AstrBot 作为核心。采用 **BORROW + BUILD**：借用成熟前端的提示词块化、Lorebook 触发和可观测配置；自己实现服务端单聊引擎、角色/记忆真源、权限隔离、prompt trace 与主动消息调度；AstrBot 只作为渠道和兼容导出适配器。

本 ADR 只冻结规格方向，不冻结具体模型 ID、价格或供应商。9router 实测尚未完成，必须在 Andrew 盲评并批准后才可改为“已接受”。

## 背景与决策驱动因素

- P0 要求 8 位角色独立单聊、流式回复、重新生成、主动消息、记忆和可回看历史。
- 角色卡、世界书和个人数据永不进入公开仓库；服务端是消息与记忆真源。
- 首批角色默认“已誓约 + 好感 200 + 满级”，不存在靠聊天自动改变基线关系的等级系统。
- 角色成长必须生成可审阅、可回滚的 diff，不能直接改写生产人设。
- 单聊要适合手机短消息，且未来要扩展到小群、多角色和主动动态。

## 决策

### 1. 模型路由

服务端只依赖 OpenAI 兼容的 `chat.completions` 抽象，不在代码中硬编码第三方地址、密钥或价格。配置提供四类逻辑路由：

| 逻辑路由 | 任务 | 选择规则 |
|---|---|---|
| `chat-primary` | 普通单聊、主动消息文案 | 由评测后的主模型承担；优先低延迟、中文自然度和人设遵循 |
| `chat-fallback` | 主模型超时、限流或 5xx | 另一家/另一档模型；失败重试必须带幂等键 |
| `memory-worker` | 摘要、长期记忆候选、成长 diff | 可用思考模型；低频、强制结构化输出、人工批准前不影响生产人设 |
| `eval-judge` | 盲样本辅助评分 | 与候选模型尽量分离；只提供参考，不参与自动选型 |

每个逻辑路由的实际 `model_id`、输入/输出美元单价、上下文上限、reasoning 开关和最大输出由私有部署配置给出。价格未知时只报告 token 数，不把别名当成价格。主聊天失败后不能偷偷切到更贵模型而不写账本。

候选模型必须通过 `pipeline/eval/chat_eval.py` 的同一套卡片、场景和采样配置比较。当前本机只观察到 `cc-pro`、`cc-normal`、`cc-lite` 三个 9router 别名，路由服务未监听，不能据此推断上游模型。

### 2. 提示词装配管线

每次生成都由一个可记录的 `PromptAssembler` 产生消息数组，顺序如下：

```text
system: 固定协议与安全边界
system: L0 角色卡（身份、描述、性格、场景、关系基线）
system: L1 命中的公共/阵营设定
system: 角色示例对话
system: mobile-chat 轻量输出约束
user/assistant: L2 近期原文窗口（尾部连续保留）
system: L3/L4 相关记忆、个人档案、命中的世界书
user: 用户最新消息
system: post-history / 当前任务的最后轻约束
```

装配器不得把所有记忆都变成长 system prompt。每块都有 `source_type`、`source_id`、`content_hash`、`priority` 和 token 估算，输出 `prompt_trace`。完整 prompt 只在私有调试权限下可读。

默认 `mobile-chat` 约束：1–4 条短消息、每次最多一个自然问题、不复述用户、不使用客服套话、不泄露内部提示、事实不确定时承认不确定。它是偏好而不是强制每条分行；角色卡的声音优先。

### 3. 记忆分层与权限

| 层 | 真源 | 注入策略 | 隔离 |
|---|---|---|---|
| L0 固定角色卡 | 角色注册表/版本库 | 每轮常驻，不能被摘要替代 | 按角色 |
| L1 公共/阵营世界书 | 可版本化 Lorebook | 关键词/正则命中，后续加语义候选 | 按公开范围 |
| L2 近期对话 | 消息服务 | 硬切窗口＋尾部保留 | `conversation_id` |
| L3 角色长期记忆 | 记忆适配器 | 关键词＋语义混合，必须带来源锚点 | 角色私聊隔离 |
| L4 个人档案 | 用户私有资料 | 相关话题才注入，最小权限 | 用户级、权限控制 |
| S 成长暂存 | diff/staging 存储 | 不直接注入，等待批准 | 角色版本 |

单聊私密内容不能自动进入其他角色的记忆。群聊只广播参与者可见的公共事件。记忆召回没有高置信来源时，宁可不引用。

成长流程固定为：聊天日志 → 后台候选事实 → `memory_diff`（含原文消息 ID/哈希和理由）→ Andrew 审阅 → 合入角色卡/世界书新版本或丢弃。合入必须可回滚；生产聊天永远不直接写 L0。

### 4. 世界书检索

第一版实现可复现的关键词/正则引擎，字段兼容 SillyTavern Lorebook 的核心概念：`keys`、`secondary_keys`、`content`、`insertion_order`、`enabled`、`source` 和预算。触发过程：

1. 扫描最近 N 条消息和用户最新消息；
2. 先做精确不区分大小写关键词与明确正则；
3. 依次检查 secondary 条件、启用状态和来源权限；
4. 按插入顺序和预算选择最多 6 条；
5. 未来才加向量候选，且需要通过关键词/语义混合评分和来源回链；
6. 将激活条目写入 `prompt_trace`，不向用户暴露“世界书”后台名词。

首版默认动态条目总预算 6000 字符；L0 和近期窗口不由 Lorebook 挤出。条目内容必须自洽，不能只写“见另一条”。

### 5. 预设与可自定义项

保留三档服务端预设作为评测基线：

- `baseline`：只加载角色卡和历史；用于诊断模型本身。
- `mobile_chat`：加手机输出协议和防 OOC 轻约束；P0 默认。
- `memory_lore`：再加相关记忆和世界书；完整单聊引擎默认。

用户可按角色覆盖温度、最大输出、主动消息类型/频率/每日上限、免打扰和世界书预算；不能在客户端修改模型密钥、服务器路由、L0 版本或其他角色的私密记忆。高级调试可查看 prompt trace 和生成来源，但不默认显示隐藏提示。

不原生实现 SillyTavern 的宏语言、任意脚本执行、前端扩展市场或完整主题系统；若日后出现真实产品需求，再以受限的服务端模板/事件 API 增加。

### 6. 主动消息

规则调度器负责“是否发送”：时间窗、免打扰、冷却键、每日上限、事实任务和去重。模型负责“怎么说”：根据 `trigger_type`、已验证事实和最近摘要生成一条短消息。发送前必须通过事实校验和相似度去重；失败进入下一窗口或丢弃，不循环重试模型绕开规则。

四类首版触发：`greeting`、`affection_chat`、`reminder`、`feed_event`。提醒的时间、标题和行动只能来自结构化任务；模型不能发明新的截止时间。

## 评测基线与验收

评测脚本位于 `pipeline/eval/chat_eval.py`，输入私有角色卡，输出：

- `blind.jsonl`：只含盲号、场景、最终回复和长对话尾部，不含模型 ID/方案名；
- `blind.md`：按场景分组的人工可读盲评材料，同样不含模型 ID/方案名；
- `mapping.private.json`：本地私有盲号映射；
- `results.private.jsonl`：延迟、token、usage、成本和每轮回复；
- `run.json`：运行元数据和成本是否可计算；
- 可选 `judge.private.jsonl`：另一个模型的 JSON 参考分。

必须覆盖 6–8 个场景，至少包含 50 轮长对话；模型候选 4–6 个，提示词方案 2–3 个。外部价格通过清单显式传入，未知时 `external_cost_usd=null`。

本轮证据：单元测试 8/8；离线夹具完整矩阵 540 次；本地 Ollama 原生接口以 `qwen3.5:9b` 真实生成 18 次；9router 因 `localhost:20128` 未监听而没有真实调用。模型排名、费用和 ADR 接受状态均待补。

## 影响与风险

### 正面影响

- 角色卡格式、AstrBot 导出和未来自建服务端可以共享同一套角色内容。
- 记忆权限与成长审批成为协议，而不是依赖某个前端的隐藏行为。
- prompt trace、usage 和 blind material 让“像不像她”的问题能回溯到模型、装配或数据来源。

### 已知风险

- 长上下文、思考 token 和不同供应商的 usage 字段会影响费用可比性；评测器会记录原始可用字段并在缺失时标记估算。
- 关键词世界书会漏召回或过度触发；语义检索上线前必须保留确定性回退和来源。
- 角色卡含游戏衍生数据时，任何 live 输出都必须留在私有 `data/`，不能贴进公开 PR 或仓库。
- 本机 9router 未运行是当前实测阻断；恢复后要重新执行验证，而不能把 Qwen 冒烟当成替代证据。

## 被拒绝的替代方案

- **ADOPT SillyTavern**：功能广，但它是创作前端，不提供啾信服务端消息真源、角色成员/设备/投递账本和本项目的记忆权限模型。
- **ADOPT AstrBot 作为大脑**：能快速接微信，但人格/知识库运行时模型不足以承担跨渠道独立成员、版本化成长和服务端历史真源。
- **FORK RisuAI/TauriTavern**：会把桌面/网页前端的状态、升级和许可边界带进 Android/服务端核心，维护成本不合算。
- **BUILD 全新角色卡标准**：没有必要；V2/V3 兼容和 Lorebook 既有生态已经足够，啾信只需在服务端建立自己的中间格式和导出适配器。

## 停止点

ADR 状态只能保持“提议”，直到 Andrew：

1. 取得 9router 4–6 模型的盲评材料并完成评分；
2. 选择主模型、备用模型和辅助模型路由；
3. 明确批准本 ADR，与 ADR-0003 一起构成设计冻结。

在此之前不修改 NAS 线上服务、不导入 AstrBot、不改生产角色卡。
