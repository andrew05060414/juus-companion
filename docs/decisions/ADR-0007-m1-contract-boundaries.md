# ADR-0007：M1 数据模型与客户端契约的边界

> 创建日期：2026-11-25 ｜ 最后更新：2026-11-25 ｜ 版本：v0.1 ｜ 状态：提议 ｜ 对应 #15

## 问题

设备离线后需要补齐消息；注册表的审核信息和推送目标却不能随客户端缓存下发。
本提议使服务端内部记录与传输对象有明确边界，不指定数据库、供应商凭据或生产配置。

## 契约

- **设备（#16）**：短期令牌只能操作自身设备。过期后重新认证，凭绑定原设备的注册凭证恢复身份和未确认账本；撤销不可通过恢复撤销前的会话来绕过。
- **角色（#17）**：公开投影只有角色编号、显示名和当前人设版本。私有审核覆盖层按角色和版本寻址；所有内容策略调用同一服务端判断，缺失或未审核绝不放宽限制。原卡、V2/V3 扩展往返和成长 diff 属于导入器，不是客户端可写字段。
- **投递（#19、#22）**：一条消息对一台设备只有一条投递记录；每次推送尝试分别关联它。推送仅唤醒，服务端回执不等于客户端落库确认。按设备顺序游标补齐，不用会随确认而变化的列表偏移。替换一轮回复时，客户端同一事务保存新消息与旧编号的删除标记，再确认。
- **消息（#15）**：传输对象的 `type/content/media_id` 对应气泡的种类、正文或服务端字幕、媒体编号；文本的媒体编号可省略或为 null。轮内回复使用非空 `turn_id` 和从零开始的 `bubble_index`。

## 版本边界

[唯一的 M1 工作草案](../openapi-draft.yaml)延续 ADR-0003 指定的位置。ADR-0005 提议的
`docs/api/openapi.yaml` 是将来冻结版的位置，不维护第二份副本。旧草案四条路径保留，
但鉴权及必填响应字段已变化；客户端与服务端应对齐草案版本，冻结稳定版另行评审。
本提议不改变 ADR-0004、0005 或 0006 的状态，也不替代后续 issue 的运行时验收。
