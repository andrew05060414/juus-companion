# 路线图与工作量

> 创建日期：2026-09-27 ｜ 最后更新：2026-09-27 ｜ 版本：v0.1
> 规划真源：本文件 + GitHub Milestones/Issues。执行由 Multica「啾信 Juus Companion」项目下的总控任务按阶段推进。

## 推进方式（AI 主导）

- 每个里程碑拆成若干 GitHub Issue；每个 Issue 对应一个 Multica 执行任务、一个分支、一个 PR。
- 同一阶段内的任务并行；一个阶段全部完成后，总控（Senior Reviewer）审查交付、决定是否推进到下一阶段。
- **Builder ≠ Reviewer**：写代码的 Agent 不审自己的 PR；高风险改动由 Senior Reviewer 审。
- 不自动合并到 main；PR 合并与 NAS 上的部署需要 Andrew 批准（见停止点）。
- Andrew 只在 🛑 停止点出现，其余时间看进度即可。

## 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 推送在 Fold 7 上被系统省电策略延迟 | 提醒不及时 | 服务端账本 + 打开补齐；安装指引设置"不受限制 / 永不休眠"；ntfy 兜底 |
| 人设质量不稳定（尤其缺啾信素材的角色） | "不像她" | 首批全审；自动质检；成长改动需审阅 |
| 上游解包数据停更或变结构 | 流水线失效 | 多数据源；导入层做版本检测与报错 |
| AI 生成代码质量 | 返工 | 每个 PR 必须有测试；Reviewer 审查；小步交付 |
| 版权与开源合规 | 下架风险 | 素材不进仓库；同人声明；发布前审计 |
